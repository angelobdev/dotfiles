# AI assistant

[← Docs](../README.md)

Claude Code stays a real terminal app, with its voice and permission prompts, and the desktop wraps it: a drop-down console, a state icon in the bar, usage meters and notifications.

## Using it

`Super + A` drops the Claude Code console down from the bar (details below); a click or tap outside, a workspace change or `Super + A` again hides it, and Claude keeps running. `Super + Shift + A` moves the active window into the console or back out. It is not in the dock: the Claude icon in the bar opens a panel with what Claude is doing, the 5-hour and 7-day usage of the subscription with their reset times, and Open / Hide console. Its dot shows Claude working (pulsing), waiting for a permission (red) or finished while the console was hidden; in those cases a notification with **Open console** arrives too.

## How it is wired

`Super + A` runs `desktop-ai`: the first press starts Claude Code (`claude`, installed in `~/.local/bin` by its installer) in a Kitty window of class `desktop-ai`, which the `desktop-ai` window rule puts on the special workspace `ai`. That workspace is a drop-down console, after the Omarchy 4.5 Quake console (`hypr/config/console.lua`):

- **Layout:** the Lua layout `lua:console` (`hl.layout.register`) tiles its windows in one box at the top of the usable area, just under the bar: 60% of the height below the bar and twice as wide (at most 92% of the width), centred, without a border. Two or more windows sit side by side across 96% of the width. The box never reaches below the docked on-screen keyboard, and it follows rotation, scale and monitor changes by itself.
- **Look:** the rest of the screen is dimmed (`decoration.dim_special = 0.45`); the console slides in from the top and back up (`specialWorkspaceIn`/`Out` in `appearance.lua`).
- **Closing:** `Super + A` again, a workspace change (`binds.hide_special_on_workspace_change`), or a click or tap anywhere outside it. Outside presses land on `desktop-console-catcher`, a transparent Bottom layer the shell maps on that screen only while the console is open (`components/ConsoleCatcher.qml`, `services/Agent.qml`); the special workspace keeps them from the windows below, so that press only closes the console.
- **New windows:** an app opened while the console is shown (`Super + Return`, the launcher, the dock) goes to the normal workspace of that monitor, and the console closes.
- **Moving windows:** `Super + Shift + A` puts the active window into the console without showing it, or takes it back out to the normal workspace (`desktop_console_move`). When Claude itself was moved out, `Super + A` brings it back in and shows the console (`desktop_console_show`).
- **Tablet mode:** the on-screen keyboard opens with the console and closes with it. Kitty keeps its text field active while the console is hidden over an empty workspace (no window takes the focus), so no activate or deactivate arrives; `services/Keyboard.qml` follows `Agent.consoleOpen` for that.

Later presses toggle the console, so the same session stays alive while hidden; closing the window ends the session and the next press starts a new one. The session starts in the dotfiles repository (found from the Stow link of `desktop-ai`), so Claude Code reads its `.claude/CLAUDE.md`; `DESKTOP_AI_DIRECTORY` names another folder, and `$HOME` is the fallback. If `claude` is missing, a notification points here.

The session gets `--settings` for this window only, so the global `~/.claude/settings.json` is untouched: voice dictation in hold mode and `language`, which Claude Code uses both for dictation and for its replies. The language comes from the system locale (`assistant.language` in the catalogs: `english`, `italian`); set `DESKTOP_AI_LANGUAGE` (e.g. `hl.env("DESKTOP_AI_LANGUAGE", "italian")` in `local.lua`, then close the assistant window) for another one.

The same `--settings` give the session a status line and hooks, both run by `libexec/desktop/agent.py`. They apply to sessions started after a change, so close the assistant window once; `/resume` in the new one continues an earlier conversation with them.

- **Hooks** (`agent.py hook`, all `async` except `SessionEnd`, so they never hold Claude up): `SessionStart` → ready, `UserPromptSubmit` and the tool events (`PostToolUse`, `PostToolUseFailure`, `PermissionDenied`) → working, `PermissionRequest` → permission (with the tool and its command or file), the `permission_prompt` notification as a fallback, `Stop` → finished (with the start of the reply), `StopFailure` → error; `SessionEnd` removes the state. The state goes to `$XDG_RUNTIME_DIR/desktop-shell/agent.json` (`session`, `state`, `detail`, `since`, `at`). Hooks run in parallel, subagents included, so the newest event wins by the time it started (a lock around the read and write). The hook prints nothing and always exits 0, whatever it receives: Claude Code adds the output of some hooks to the conversation and treats exit code 2 as an answer (keep going after `Stop`, deny a permission).
- **Status line** (`agent.py statusline`): the documented status line JSON gives `rate_limits.five_hour` and `seven_day` (percent used, reset time) for claude.ai subscribers after the first reply of a session, plus the model and the context use. They go to `~/.local/state/desktop-shell/agent-usage.json` with the plan tier from `~/.claude.json` (`oauthAccount.organizationRateLimitTier`, no token is read); without `rate_limits` the previous limits stay with their time, and a missing window is shown as unknown, not 0%. The terminal gets `Opus 5.5 · context 34% · 5h 24% · 7d 41%`. No undocumented usage endpoint is called, so the numbers are as of the last reply.
- **Shell** (`services/Agent.qml`): the Claude icon in the bar (shown when `claude` is installed) carries a dot: pulsing accent while Claude works, red while it waits for a permission or after an error, steady accent when it finished while the console was hidden. While the console is hidden, a notification says that Claude is asking for a permission (with the command) or has finished (with the start of the reply), with **Open console** (a click on the popup does the same); opening the console clears the dot and closes those notifications. Do Not Disturb keeps them out of the popups. Notifications are only for changes, so a shell restart does not repeat one.
- **Panel** (a click on the icon, or `desktop-shell toggle agent`): the state and its detail, the plan (`Max 5x`), the 5-hour and 7-day meters with their reset times (red from 90%), when the limits were last read, the model and context, and Open / Hide console.

Hold `Space` in the prompt to record, release to insert the transcript, `Esc` to cancel; a single tap still types a space. Hold detection relies on keyboard repeat, so recording starts after Hyprland's repeat delay. Transcription runs on Anthropic's servers and needs Claude Code signed in with a claude.ai account: `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN` or an `apiKeyHelper` take precedence and disable it (`/voice` then reports an unknown command; run `/login`). Recording uses Claude Code's native module and falls back to `arecord` (installed) or SoX `rec`.
