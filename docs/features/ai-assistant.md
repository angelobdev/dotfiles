# AI assistant

[← Docs](../README.md)

Terminal coding agents stay real terminal apps, with their own prompts, approvals and slash commands, and the desktop wraps them: a drop-down console, a state icon in the bar, live activity details, optional usage meters and notifications.

## Supported coding agents

`desktop-ai` and `libexec/desktop/agent.py` support **Antigravity** (`antigravity` or `agy`), **Claude Code** (`claude`), **Codex** (`codex`), **Gemini CLI** (`gemini`), **OpenCode** (`opencode`), **Pi** (`pi`), or any custom CLI command:

1. `DESKTOP_AI_AGENT` in the environment (for example `hl.env("DESKTOP_AI_AGENT", "codex")` in `~/.config/desktop/hypr.lua`) wins when set.
2. Otherwise **Settings → Assistant → Coding agent** (`"aiAgent"` in `~/.config/desktop/shell.json`, e.g. `"antigravity"`, `"claude"`, `"codex"`, `"gemini"`, `"opencode"`, `"pi"`, or a custom command such as `"aider"`).
3. When unset (`Automatic`), the first installed harness in the order above is used.

## Using it

`Super + A` drops the assistant console down from the bar (details below); a click or tap outside, a workspace change or `Super + A` again hides it, and the agent keeps running. `Super + Shift + A` moves the active window into the console or back out. `Super + Ctrl + A` selects a screen area, launches the console if it is not running yet, formats the image reference for the active harness (`@/path/to/image.png` for Antigravity and Gemini CLI, plain `/path/to/image.png` for Claude Code, Codex, OpenCode, Pi and custom commands), types it into the prompt and opens the console. `desktop-ai here` (or **Open in active folder** in the assistant panel) starts or restarts the console in the working folder of the focused terminal or editor window (`agent.py cwd`). It is not in the dock: the assistant icon in the bar (named after the active agent, e.g. **Antigravity** or **Claude**) opens a panel with what the agent is doing, the active session folder, rate-limit meters when the agent reports them, model and context use, **Open / Hide console**, **Open in active folder**, and **Restart with …** if a different coding agent was chosen in Settings while a session was already open. Its dot shows the agent working (pulsing), waiting for a permission or after an error (red), or finished while the console was hidden; in those cases a notification with **Open console** arrives too.

## How it is wired

`Super + A` runs `desktop-ai`: the first press resolves the configured or detected coding agent (`agent.py launch`) and starts it in a Kitty window of class `desktop-ai`, which the `desktop-ai` window rule puts on the special workspace `ai`. That workspace is a drop-down console, after the Omarchy 4.5 Quake console (`hypr/.config/hypr/config/console.lua`):

- **Layout:** the Lua layout `lua:console` (`hl.layout.register`) tiles its windows in one box at the top of the usable area, just under the bar: 60% of the height below the bar and twice as wide (at most 92% of the width), centred, without a border. Two or more windows sit side by side across 96% of the width. The box never reaches below the docked on-screen keyboard, and it follows rotation, scale and monitor changes by itself.
- **Look:** the rest of the screen is dimmed (`decoration.dim_special = 0.45`); the console slides in from the top and back up (`specialWorkspaceIn`/`Out` in `appearance.lua`).
- **Closing:** `Super + A` again, a workspace change (`binds.hide_special_on_workspace_change`), or a click or tap anywhere outside it. Outside presses land on `desktop-console-catcher`, a transparent Bottom layer the shell maps on that screen only while the console is open (`components/ConsoleCatcher.qml`, `services/Agent.qml`); the special workspace keeps them from the windows below, so that press only closes the console.
- **New windows:** an app opened while the console is shown (`Super + Return`, the launcher, the dock) goes to the normal workspace of that monitor, and the console closes.
- **Moving windows:** `Super + Shift + A` puts the active window into the console without showing it, or takes it back out to the normal workspace (`desktop_console_move`). When the assistant window itself was moved out, `Super + A` brings it back in and shows the console (`desktop_console_show`).
- **Tablet mode:** the on-screen keyboard opens with the console and closes with it. Kitty keeps its text field active while the console is hidden over an empty workspace (no window takes the focus), so no activate or deactivate arrives; `services/Keyboard.qml` follows `Agent.consoleOpen` for that.

Later presses toggle the console, so the same session stays alive while hidden; closing the window ends the session and the next press starts a new one (`desktop-ai restart` restarts it in place). Each launch records the running harness and directory in `$XDG_RUNTIME_DIR/desktop-shell/agent-session.json` so session watching stays pinned to the running window even if **Settings → Assistant** changes beforehand. By default the session starts in the dotfiles repository (found from the Stow link of `desktop-ai`); **Settings → Assistant → Working folder** (`"aiDirectory"` in `~/.config/desktop/shell.json`) or `DESKTOP_AI_DIRECTORY` names another default folder, `desktop-ai here` opens in the active window's folder, and `$HOME` is the fallback. If the chosen agent (or any supported agent) is missing, a notification points here.

### State, telemetry and per-harness settings

Global agent configuration files (`~/.claude/settings.json`, `~/.codex/`, `~/.gemini/`) are never modified automatically; each harness integration is isolated to its own mechanism:

- **Event-driven session watching for Antigravity, Codex and Gemini CLI** (`agent.py watch <agent>`): while a non-Claude `desktop-ai` window is open, `services/Agent.qml` runs `agent.py watch` (with `setpriv --pdeathsig TERM`), using Linux `inotify` (`InotifyWatcher`) for zero-idle-CPU wakeups on local session logs — `~/.gemini/antigravity-cli/brain/<id>/.system_generated/logs/transcript.jsonl` (plus `settings.json` for model and context window) for Antigravity, `~/.codex/sessions/` for Codex, and `~/.gemini/tmp/*/chats/session-*.json` for Gemini CLI. It writes live state (`ready`, `working`, `permission`, `finished`, `error`) and tool or reply previews to `$XDG_RUNTIME_DIR/desktop-shell/agent.json`, updates model and context percentage in `~/.local/state/desktop-shell/agent-usage.json`, and removes `agent.json` and `agent-session.json` when the console window closes. Other CLI harnesses (`opencode`, `pi`, or custom commands) report `ready` while running.
- **Antigravity opt-in quota and status line** (`agent.py agy-statusline on|off|status`): shown in **Settings → Assistant** only when Antigravity is the active agent. Turning it on sets `statusLine` in `~/.gemini/antigravity-cli/settings.json` (preserving all other keys) so Antigravity feeds live quota buckets, reset times, plan tier and authoritative model/context data to `agent.py statusline`; turning it off clears our hook without touching custom user `statusLine` commands.
- **Claude Code `--settings`, hooks and voice**: when the active agent is `claude`, `desktop-ai` passes `--settings` for that window only, enabling hold-Space voice dictation, `language` (from the system locale `assistant.language`, **Settings → Assistant → Language** — shown for Claude Code — or `DESKTOP_AI_LANGUAGE` in `~/.config/desktop/hypr.lua`), async lifecycle hooks (`agent.py hook`: `SessionStart`, `UserPromptSubmit`, `PostToolUse*`, `PermissionDenied`, `PermissionRequest`, `Stop`, `StopFailure`, `SessionEnd`), and `agent.py statusline`. Hooks run in parallel with a lock so the newest event wins, print nothing and always exit 0.
- **Status line and rate limits** (`agent.py statusline`): reads Claude Code's documented status line JSON (`rate_limits.five_hour` and `seven_day`, plus plan tier from `~/.claude.json`) as well as Antigravity's `StatusLineData` JSON (`quota` buckets — including exhausted buckets where `remaining_fraction` is omitted — and `plan_tier`), saving them to `~/.local/state/desktop-shell/agent-usage.json` tagged with the agent ID so limits from one harness never bleed into another.
- **Shell and panel** (`services/Agent.qml`, `panels/AgentPanel.qml`, `panels/agent/AgentView.qml`): the bar icon (shown when an agent is installed or `Config.aiAgent` is set) carries a dot: pulsing accent while working, red while waiting for permission or after an error, steady accent when finished while the console was hidden. Hidden-console transitions send a notification naming the active agent with **Open console**; opening the console clears the dot and dismisses them. The panel and **Settings → Assistant** show the agent's state, detail, model and context, Open / Hide console, and rate-limit meters only when the active agent reports limits (`Agent.hasLimits`).

In Claude Code, hold `Space` in the prompt to record, release to insert the transcript, `Esc` to cancel; a single tap still types a space. Hold detection relies on keyboard repeat, so recording starts after Hyprland's repeat delay. Transcription runs on Anthropic's servers and needs Claude Code signed in with a claude.ai account (`ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN` or an `apiKeyHelper` disable `/voice`; run `/login`). Recording uses Claude Code's native module and falls back to `arecord` (installed) or SoX `rec`.
