# On-screen keyboard

[← Docs](../README.md)

A keyboard written for this shell: slide between keys, likely letters are easier to hit, word suggestions in Italian and English, and it learns your words without ever leaving the machine.

## Using it

Opened from the assist button (Keyboard, or a long press on the button) or with `desktop-shell keyboard show|hide|toggle`. It never takes focus: keys go to the window that has it, as from the physical keyboard, with the same Italian layout.
- **Automatic:** in tablet mode, tapping into a text field opens it, on the digits page for number and PIN fields and with the extra row in a terminal; leaving the field closes it again, unless it was opened by hand. Leaving tablet mode closes an automatic keyboard. **On the lock screen** in tablet mode the docked keyboard shows over hyprlock for the password, with the password field and the user name moved up above it (`desktop-power lock` tells the shell when the lock starts and ends). This works in apps that report text fields (text-input-v3): GTK and libadwaita apps, Zen/Firefox, Qt 6 and Kitty. Electron and Chromium apps (VS Code) report them only when started with `--enable-wayland-ime --wayland-text-input-version=3`; there the keyboard still opens from the assist button. `Config.oskAutoShow: false` turns it off.
- **Docked** (the default): full width at the bottom of the built-in display, keys 64 px tall (about 11 mm on the 14" panel) and centred up to 1100 px; windows shrink above it. **Floating**: up to 900 px wide with 56 px keys, over the windows, moved by dragging its top strip. The strip switches between the two (`desktop-shell keyboard float|dock`) and hides the keyboard; the choice is remembered.
- **Pages:** letters, `?123` (digits and common symbols) and `=\<` (brackets, braces and the rest). Shift applies to the next key; a quick second tap locks it. The small character in a corner is what Shift types.
- **Typing:** a key types when the finger lifts, and the one that counts is the key under it: the highlight follows a sliding finger, and the gaps between keys belong to the nearest key. A second finger commits the first at once, so two thumbs keep their order.
- **Prediction:** in ordinary text fields, a letter likely to come next is a little easier to hit, as on iOS, from Italian and English word frequencies. The keys look the same and grow by at most a fifth of their height towards their neighbours, so a touch well inside a key stays on it. It stays out of passwords and hidden fields, terminals, URLs, email addresses, numbers and the lock screen. The word lists are downloaded the first time it is needed; until then, or without a network, the keys simply keep their edges.
- **Suggestions:** while you type a word, the strip above the keys offers up to three that finish it, in Italian or English. A tap completes the word and adds a space, and fixes an accent left out (`perche` becomes `perché`). They appear where the prediction works, wait while Caps Lock is on, and give way to the accents after a long press. Nothing is suggested before the first letter of a word.
- **Learning:** the keyboard learns the words you finish in ordinary text fields, and those rise among the suggestions; a new word appears after two uses, so a single typo stays out. Hold a suggestion for a moment to never see it again. It learns nothing from passwords and hidden fields, terminals, URLs, email addresses, numbers, the lock screen, or apps that do not say what kind of field they have. It keeps only single words and how often they were used, with no order and no time, in a file only you can read: `~/.local/state/desktop-shell/osk-words.json`. Delete that file and restart the shell to start over.
- **Accents:** a long press on a, e, i, o or u offers à, è, é, ì, ò, ù in the strip, where the finger can slide or tap; any other key held types once. Backspace repeats while held.
- **Space** goes down and up with the finger, like a physical key: held, it repeats, so Claude Code's hold-to-talk works from the on-screen keyboard too.
- **With panels:** a panel opening over a keyboard that a field opened (the terminal behind) closes it, unless the panel focuses a field of its own (the launcher search); a keyboard opened by hand stays. Panels then sit in the area above the docked keyboard (centred dialogs and side panels shrink to fit, the Control Center scrolls), the keyboard is mapped again on top of them, and an open panel takes no input inside its rectangle. In tablet mode Network, Clipboard and Hints do not focus their search field, so they open without the keyboard; a tap on the field brings it.
- **Dock:** from the assist button in tablet mode the dock comes up for touch: no keyboard surface (Super + D keeps it), it stays while tapped and goes 6 s after the last tap or once an app opens (`desktop-shell dock touch`).
- **More keys** (the keyboard button on the strip) adds Esc, Tab, Ctrl, Alt and arrows; Ctrl and Alt apply to the next key.

## Configuration

- **Layout:** `osk/layouts/<Config.oskLayout>.json` (`it`): pages of rows, each key an evdev code with its label, optional modifier mask (Shift 1, Ctrl 4, Alt 8, AltGr 128) and Shift label; rows are 10 units wide. `accents` lists the long-press variants and `extra` the optional row. `test_osk.py` checks every label against what the key types in the XKB keymap.
- **Typing:** `libexec/desktop/osk.py run`, started the first time the keyboard opens and then kept, creates a `zwp_virtual_keyboard_v1` with the keymap of Hyprland `input:kb_layout`/`kb_variant`/`kb_options` (compiled by libxkbcommon), so keys mean what the physical keyboard would. The shell writes `key CODE MODS` lines to it. It speaks the Wayland wire protocol directly: no packages beyond Python and libxkbcommon. `osk.py check CODE MODS` prints what a key types.
- **Automatic opening:** with `Config.oskAutoShow` the helper starts with the shell as `osk.py run --input-method` and also binds `zwp_input_method_v2`, only as a signal: activate, deactivate and the content purpose (applied on `done`) become `{"event": "activate", "purpose": ...}` / `{"event": "deactivate"}` lines. Text still goes through the virtual keyboard, which works in every app. It needs no IBus or fcitx; if another input method holds the seat, the protocol reports `unavailable` and the keyboard opens only by hand. A field change waits 300 ms before closing, so moving between fields does not flicker.
- **Prediction:** `Config.oskPrediction` turns it on. `predict.py` reads the Italian and English lists of [FrequencyWords](https://github.com/hermitdave/FrequencyWords) (CC-BY-SA-4.0), pinned by commit and hash, fetched on first use into `~/.local/share/desktop/keyboard/` and never committed. `osk.py` answers `predict WORD` with the likely next letters and up to three completions; `osk/KeyScore.js` lets those keys grow by up to `KeyScore.REACH` of the key height. A suggestion is typed with ordinary keys (`Keyboard.complete()`), never committed through the input method, so it behaves the same in every app. Accent variants are filtered: a form is kept only if the accented word is less than half as common as the plain one, since subtitles often drop accents (`misspelled()` in `predict.py`). Nothing typed is sent anywhere. `Config.oskLearning` counts finished words in `osk-words.json` in the state directory (`{"counts", "forgotten"}`, mode 0600, keys sorted so the file shows no order, at most 5,000 words); `Keyboard.learning` limits it to fields that report a purpose of normal, alpha or name. `Config.oskTouchStats` keeps totals of how far touches land from the centre of their letter (`oskTouch` in `session.json`, shown by `desktop-shell status`), never which letter or when.
- **Panels in tablet mode** take the keyboard focus on demand instead of exclusively (`Overlay.qml`, the polkit and Bluetooth dialogs): an exclusive layer received every touch, so the keys of the on-screen keyboard never reached it.
- **Lock screen:** in tablet mode `desktop-power lock` gives hyprlock a copy of its config in `$XDG_RUNTIME_DIR` with `fingerprint:enabled = false` (hyprlock reads the reader itself, not through PAM) (its password placeholder and fingerprint messages come from the i18n catalogs, `lockScreen.*`, rendered by theme.py) and every widget anchored to the bottom (user, password field, messages) lifted so the field sits above the docked keyboard with the gap the config keeps between the field and the user name. The keyboard height comes from `desktop-shell status` after the keyboard is shown, in logical pixels, times the monitor scale, as hyprlock positions are physical pixels. It runs `desktop-shell keyboard locked` before hyprlock and `unlocked` after it (no longer `exec`, so it sees the end). In tablet mode `locked` shows the docked keyboard; the `desktop-osk-lock` layer rule (`above_lock = 2`) draws it over the lock and lets it take touches.
- **Surfaces:** layer namespace `desktop-osk`, blurred like the panels. Docked it is an Overlay layer anchored to the bottom with an exclusive zone (re-mapped for 60 ms when a panel opens, so it stays above it); floating, a full-screen Overlay layer whose input region is the keyboard. Neither takes keyboard focus.
